# Автономный агент на Llama (Ollama) — контекст задачи для Codex

## Цель проекта

Создать автономного агента на базе локальной LLM (Ollama), который:
- Самостоятельно **планирует следующий запуск** (сам себе устанавливает таймер)
- Имеет **внешнюю систему памяти** (вне базового контекста модели)
- Работает на **слабом ПК** (малый контекст, лёгкая модель)
- Написан на **Node.js**

---

## Стек

| Компонент | Инструмент |
|---|---|
| Модель | Ollama REST API `http://localhost:11434` |
| Планировщик | `node-cron` |
| HTTP | `axios` |
| Файлы памяти | `fs-extra` + JSON |
| Конфиг | `dotenv` |

## Архитектура (компоненты и их роли)

```
agent/
├── index.js              ← точка входа, главный цикл
├── scheduler.js          ← управление таймером wake-up
├── context_builder.js    ← сборка промпта из памяти
├── output_parser.js      ← парсинг тегов из ответа модели
├── memory_manager.js     ← CRUD операции над JSON-файлами памяти
└── config.js             ← параметры (модель, лимиты токенов и т.д.)

memory/
├── short_mem.json        ← краткосрочная память (активные задачи, мысли)
└── long_mem.json         ← долгосрочная память (выводы, архив, знания)

.env                      ← конфиг окружения
```

## Формат памяти

### `memory/short_mem.json`
```json
[
  {
    "id": 1,
    "type": "task",
    "content": "Обдумать подход к теме X",
    "priority": "high",
    "created": "2024-01-01T10:00:00Z",
    "expires": null
  }
]
```
`type` может быть: `task` | `thought` | `plan` | `reminder`

### `memory/long_mem.json`
```json
[
  {
    "id": 101,
    "type": "insight",
    "content": "Вывод по теме Z: ...",
    "tags": ["тема"],
    "created": "2024-01-01T10:00:00Z",
    "source": "session_42"
  }
]
```
`type` может быть: `insight` | `archived_task` | `knowledge` | `reflection`

## Теги в ответе модели (управляющий протокол)

Модель ОБЯЗАНА завершать каждый ответ блоком тегов. Парсер читает только эти теги.

```
[MEM_SAVE short] {"type":"task","content":"...","priority":"normal"}
[MEM_SAVE long]  {"type":"insight","content":"...","tags":["тема"]}
[MEM_DELETE short 5]
[MEM_DELETE long 102]
[SCHEDULE 3600]
[REFLECT]
```

| Тег | Действие |
|---|---|
| `[MEM_SAVE short]` | Добавить запись в краткосрочную память |
| `[MEM_SAVE long]` | Добавить запись в долгосрочную память |
| `[MEM_DELETE short <id>]` | Удалить запись из краткосрочной памяти |
| `[MEM_DELETE long <id>]` | Удалить запись из долгосрочной памяти |
| `[SCHEDULE <секунды>]` | Установить таймер следующего запуска |
| `[REFLECT]` | Запустить рефлексию: сжать short_mem → long_mem |

## Системный промпт агента (вставляется в каждый запрос)

```
Ты — автономный агент-рефлексор. Работаешь самостоятельно без пользователя.

Твоя память находится вне этого контекста — управляй ей через теги в конце ответа.

=== КРАТКОСРОЧНАЯ ПАМЯТЬ (активное) ===
{{SHORT_MEM}}

=== ДОЛГОСРОЧНАЯ ПАМЯТЬ (релевантное) ===
{{LONG_MEM}}

=== ТЕКУЩЕЕ ВРЕМЯ ===
{{DATETIME}}

Инструкции:
1. Обдумай что-то полезное, развей идею или выполни задачу из памяти.
2. В конце ОБЯЗАТЕЛЬНО укажи теги управления памятью и следующий запуск.
3. [SCHEDULE X] — через сколько секунд ты хочешь снова подумать (минимум 60).
4. Если краткосрочных задач накопилось >10 — добавь тег [REFLECT].

Отвечай на русском языке.
```

---

## Ключевые правила реализации

1. **Контекст ограничен** — в промпт вставлять не более 5 записей из `short_mem` и не более 5 из `long_mem` (сортировка: short — по priority+дате, long — по дате).

2. **Парсер тегов** — теги ищутся в последних 30 строках ответа, регуляркой. Всё что до тегов — это «мысль агента», логируется в `logs/`.

3. **Планировщик** — после парсинга `[SCHEDULE X]` вызывает `setTimeout(runAgent, X * 1000)`. Если тег отсутствует — дефолт из `.env` (`DEFAULT_INTERVAL_SEC`).

4. **Рефлексия** (`[REFLECT]`) — отдельный вызов к модели с промптом: *«Сожми эти краткосрочные записи в 3-5 ключевых вывода для долгосрочной памяти»*, результат сохраняется в `long_mem`, `short_mem` очищается от выполненных задач.

5. **Атомарные записи** — перед каждой записью в JSON делать `JSON.parse(fs.readFileSync(...))`, после — `fs.writeFileSync(...)`. Без in-memory кэша (агент может перезапуститься).

6. **Логирование** — каждый запуск пишет файл `logs/YYYY-MM-DD_HH-MM.txt` с полным ответом модели.

## Файл `.env`

```env
OLLAMA_HOST=http://localhost:11434
MODEL_NAME=llama3.2
DEFAULT_INTERVAL_SEC=3600
MAX_SHORT_MEM_IN_CONTEXT=5
MAX_LONG_MEM_IN_CONTEXT=5
MAX_TOKENS=1024
LOG_DIR=./logs
MEMORY_DIR=./memory
```

## Порядок создания файлов Codex-ом (оптимальная последовательность)

1. `package.json` + `.env` + папки `memory/` `logs/` `agent/`
2. `memory/short_mem.json` и `memory/long_mem.json` (пустые массивы `[]`)
3. `agent/config.js` — загрузка `.env`
4. `agent/memory_manager.js` — read/write/delete для обоих файлов
5. `agent/output_parser.js` — парсинг тегов регуляркой
6. `agent/context_builder.js` — сборка промпта из памяти
7. `agent/scheduler.js` — setTimeout / управление таймером
8. `agent/index.js` — главный цикл: запрос → парсинг → действия → планирование
9. Проверочный запуск: `node agent/index.js`

## Ограничения и допущения

- ПК слабый → модель `llama3.2` (3B) или `phi3:mini`, `max_tokens` не более 1024
- Нет векторного поиска — память ищется простым перебором + сортировкой
- Нет веб-интерфейса — только консоль и лог-файлы
- Один агент, один поток — без параллельных запросов
- Ollama должна быть запущена (`ollama serve`) до старта агента
